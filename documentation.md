# Документация проекта поиска по корпусу

## 1. Назначение проекта
Проект реализует поиск по текстовому корпусу Reddit (CSV) с тремя моделями ранжирования:
- BM25
- Word2Vec
- FastText

Поддерживаются два интерфейса:
- CLI (консольный запуск)
- Web (Flask-приложение)

Общий сценарий поиска вынесен в единый сервис, чтобы логика не дублировалась между CLI и web.

## 2. Структура и роли файлов
- main.py: CLI-вход, парсинг аргументов, интерактивные вопросы, вывод результатов
- search_service.py: единый сценарий поиска (валидация, загрузка/кеш, предобработка, сборка модели, поиск)
- corpus.py: загрузка CSV, очистка/токенизация/лемматизация, создание документов, кеш предобработки
- search_engine.py: реализация моделей BM25 / Word2Vec / FastText и общий метод поиска
- web/app.py: Flask-интерфейс (форма, запуск поиска, рендер результатов)
- data/reddit_ct.csv: исходный корпус
- data/preprocessed_cache.pkl: кеш предобработанного корпуса

## 3. Как работает поиск (пошагово)
Поиск выполняется в search_service.run_search:
1. Валидация входных параметров (модель, запрос, limit, top_k)
2. Инициализация текстового процессора
3. Загрузка предобработанного корпуса из кеша (если валиден)
4. Если кеш невалиден/отсутствует: чтение CSV и предобработка документов
5. Сохранение свежего результата предобработки в кеш
6. Предобработка пользовательского запроса
7. Инициализация поискового движка
8. Сборка выбранной модели
9. Выполнение поиска и возврат top_k результатов

Возвращаемый результат:
- results: список найденных документов с score
- search_time: время поиска
- stats: статистика (если включен verbose)

## 4. Модели и принцип работы
### BM25
- Использует токены документов
- Считает релевантность по классической вероятностной формуле BM25
- Быстро строится, хорошо работает как базовая модель

### Word2Vec
- Обучает эмбеддинги слов на корпусе
- Вектор документа: среднее векторов слов документа
- Вектор запроса: среднее векторов слов запроса
- Ранжирование: косинусная близость

### FastText
- Похож на Word2Vec, но учитывает подсловные структуры
- Лучше переносит редкие и морфологически измененные формы
- Ранжирование также через косинусную близость

## 5. Предобработка текста
В corpus.py используется легкая и быстрая схема для английского текста:
1. Удаление ссылок
2. Нормализация пробелов и переносов строк
3. Приведение к нижнему регистру
4. Извлечение токенов регулярным выражением
5. Удаление стоп-слов
6. Лемматизация через NLTK WordNetLemmatizer
7. Обновление множества уникальных слов

Почему так:
- Эта схема быстрее на Windows, чем внешний MyStem
- Логика согласована с английскими стоп-словами

## 6. Кеш предобработки
Чтобы не выполнять тяжелую предобработку на каждом запуске, добавлен файловый кеш.

Файл кеша:
- data/preprocessed_cache.pkl

Что хранится в кеше:
- Список документов (title, text, tokens)
- unique_words
- rows_loaded
- Служебные поля для валидации

Условия валидности кеша:
- Совпадает путь к исходному CSV
- Совпадает время изменения CSV (mtime)
- Совпадает limit

Если любое условие не выполнено:
- Кеш игнорируется
- Корпус предобрабатывается заново
- Новый кеш перезаписывается

## 7. CLI: аргументы и интерактивный режим
CLI реализован в main.py.

Поддерживаемые аргументы:
- --model: bm25 | word2vec | fasttext
- --query: текст запроса
- --limit: сколько строк брать из корпуса
- --top-k (или --count): сколько результатов вернуть
- --verbose: вывод расширенной статистики

Особенность поведения:
- Если часть аргументов не передана, программа задает вопросы интерактивно
- То есть можно запускать как полностью из CLI, так и в полуинтерактивном режиме

Проверки:
- model должен быть из списка поддерживаемых
- query не должен быть пустым
- limit и top_k должны быть >= 1

## 8. Web-интерфейс
Web-часть находится в web/app.py и использует Flask.

Маршруты:
- GET /: отображает форму поиска
- POST /search: получает поля формы, запускает run_search и возвращает результаты

Параметры формы:
- query
- model
- limit
- top_k
- verbose

Web переиспользует тот же search_service.run_search, что и CLI.
Это гарантирует единое поведение и единый механизм кеширования.

## 9. Логи и фазы выполнения
Во всех ключевых модулях добавлены прогресс-логи вида:
- Starting phase ...
- Finished phase ...

Есть простые флаги отключения логов:
- main.py: ENABLE_LOGS
- web/app.py: ENABLE_LOGS

Если флаг False, логирование отключается через logging.disable(logging.CRITICAL).

## 10. Работа с кодировкой в Windows CLI
В main.py добавлена защита для вывода Unicode:
- Перенастройка stdout/stderr в utf-8 (если доступно)
- Безопасное преобразование текста перед print

Это предотвращает падение вида UnicodeEncodeError при выводе сниппетов в консоль с legacy-кодировкой.

## 11. Ограничения текущей реализации
- WordNetLemmatizer не делает POS-tagging, поэтому лемматизация упрощенная
- Прогресс-лог в create_documents сейчас очень частый (каждая строка)
- Кеш рассчитан на один источник CSV и limit; для более сложных сценариев нужна расширенная схема версионирования

## 12. Быстрые команды запуска
CLI:
python main.py --model bm25 --query "covid" --limit 2000 --top-k 5 --verbose

Web:
python web/app.py --host 127.0.0.1 --port 5000

После запуска web откройте браузер и перейдите на:
http://127.0.0.1:5000
